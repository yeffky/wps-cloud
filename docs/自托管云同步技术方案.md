# WPS 自托管云同步插件技术方案

## 1. 目标

实现一个安装在 WPS 桌面客户端中的个人加载项。用户可以配置自己的文件服务器地址、访问令牌和云端目标目录。用户从本地任意位置打开支持的文档并保存后，加载项捕获保存事件并将文档上传至自有服务器；云服务不依赖 WPS 会员空间。

首期不做多人实时协同，不修改或替换 WPS 原生“云文档”服务，也不要求用户通过 OA 网页启动 WPS。加载项使用 HTML/JavaScript 构建，但界面和交互位于 WPS 的功能区与任务窗格。

## 2. 总体结构

```text
┌──────────────────────────── WPS 桌面端 ────────────────────────────┐
│ “个人云盘”加载项                                                    │
│ 设置面板 / 目录选择 / 同步状态 / 保存事件监听                        │
│                  │ WPS JSAPI FileAfterSave + OAAssist.UploadFile    │
└──────────────────┼─────────────────────────────────────────────────┘
                   │ HTTPS
                   ▼
┌──────────────────────── 自托管文件服务 ────────────────────────────┐
│ Bearer API ─ 文件目录和元数据 ─ 短时签名票据 ─ 版本冲突校验          │
└──────────────────┼─────────────────────────────────────────────────┘
                   ▼
        本地磁盘 / NAS / 后续可替换为 S3 兼容对象存储
```

## 3. 保存同步流程

1. Writer、ET、WPP 分别通过 WPSJS 的 `wps`、`et`、`wpp` 类型注册同一加载项，共享界面和同步逻辑；这是三种组件注册入口，不是三套独立插件。ET、WPP 调试入口位于 `client/addin/targets/et/` 与 `client/addin/targets/wpp/`，从 `client/addin/` 分别运行 `npm run debug:et` 和 `npm run debug:wpp`。事件按组件类型注册：Writer 使用 `FileAfterSave`/`DocumentChange`/`ContentChange`，ET 使用 `FileAfterSave`/`SheetChange`，WPP 使用 `FileAfterSave`/`WindowSelectionChange`。
2. 保存后从事件参数中的文档对象读取 `FullName`；兼容回退到 `Application.ActiveDocument.FullName`。路径必须是本地文件路径，忽略尚未保存、网络 URL 和不支持的扩展名。
3. 对本地绝对路径做规范化并计算 SHA-256。客户端只将路径摘要和随机机器 ID 发送给服务端，避免上传本机用户名和目录结构。
4. 客户端使用 Bearer Token 请求 `POST /api/sync-ticket`，提交文件名、路径摘要、机器 ID、目标目录以及本地已知的云端文件 ID/版本。
5. 服务端检查版本，返回一个短时上传票据和文件 ID。客户端调用 `OAAssist.UploadFile(fileName, filePath, uploadUrl, "file", success, fail)`，直接从已保存文件上传。长期密钥不放在加载项上传 URL 中。
6. 服务端校验票据、大小、文件名、目标路径与期望版本，将文件写为新版本并原子更新元数据。版本不一致时返回冲突，不覆盖已有远端版本。
7. 客户端更新本地同步状态。失败任务进入重试队列；本地文件仍是有效保存结果。

### 3.1 可选定时差异检查与同步

- 面板中的“自动检测本地与云端差异并同步”开关默认关闭，配置保存在加载项本地设置中。
- 开启后 Writer 监听 `DocumentChange`/`ContentChange`，ET 监听 `SheetChange`，WPP 以 `WindowSelectionChange`（选区变化）作为近似触发信号。WPP 本地文件路径优先取 `FullName`，不可用时将目录 `Path` 与文件名 `Name` 合并。默认连续空闲 5 秒（可设 1–60 秒）后，WPP 会检查 `Presentation.Saved`，仅在明确为未保存状态时调用 `Save()`，再将文件加入同步队列。WPS 官方 WPP 事件表没有公开内容变化事件，因此此适配不能保证每次文本输入或对象修改都会重置计时。保存后对已有本地映射的文件使用 `Application.FileSystem.readAsBinaryString` 读取磁盘内容并计算 SHA-256，再与服务端当前版本摘要比较；首次上传会创建云端映射。
- 内容一致时只更新客户端已知云端版本号，不创建多余的云端版本；内容不同且云端仍处于客户端已知版本时，自动上传本地文件，服务端保存为新版本。
- 若云端版本已在其他客户端更新且内容也不同，则提示冲突并停止自动覆盖。新文档需先通过一次保存同步建立本地路径到云端文件 ID 的映射。
- 此开关独立于“保存后自动同步”：空闲后自动调用当前文档的 `Save()`，然后将本地文件加入云端同步队列；新文件也可由此建立首次云端映射。另保留每 60 秒的比较检查，用于检测本地磁盘上的外部修改，但会跳过 WPS 当前仍处于未保存状态的文档。“保存后自动同步”则负责响应用户主动保存事件。
- 空闲保存依赖目标 WPS 版本支持对活动文档调用 `Save()`；每 60 秒的差异检查还会读取 `Saved` 属性并跳过未落盘文档。内容摘要依赖 `FileSystem.readAsBinaryString`，该接口读取完整文件内容并可能占用较多内存，需在目标客户端验证大文件表现。
- WPS 官方加载项事件文档列出了文字组件的 `DocumentChange`/`ContentChange`，ET 的 `SheetChange`（参数为工作表和变更区域），以及 WPP 的 `WindowSelectionChange`（参数为选区对象）。WPP 文档未列出内容变化事件；`Presentation.Saved`/`Save()` 可用于检查和保存未保存的演示文稿。[文字事件说明](https://open.wps.cn/documents/app-integration-dev/wps365/client/wpsoffice/jsapi/addin-api/event/wps-event)、[ET 事件说明](https://open.wps.cn/documents/app-integration-dev/wps365/client/wpsoffice/jsapi/addin-api/event/et-event)、[WPP 事件说明](https://open.wps.cn/documents/app-integration-dev/wps365/client/wpsoffice/jsapi/addin-api/event/wpp-event)、[Presentation.Saved 属性](https://open.wps.cn/documents/app-integration-dev/wps365/client/wpsoffice/jsapi/wpp/Presentation/member/Saved)

WPS 官方加载项 API 文档列出 `FileAfterSave` 保存后事件、`OAAssist.UploadFile` 本地文件上传方法，以及 `OAAssist.DownloadFile` 下载方法。具体事件参数和另存为、自动保存覆盖情况需按使用的 WPS 版本实测。首版采用保存后异步上传，避免网络延迟阻塞 WPS 的本地保存。

## 4. 本地文档映射、云端缓存与冲突处理

- 第一次保存的文件：以 `machineId + pathHash` 作为客户端映射键，服务端创建独立的云文件 ID。
- 后续保存：通过相同映射更新该云文件的新版本。
- 同名不同路径文件：各自有独立映射和 ID，不按文件名覆盖。
- 云端版本已被其它设备更新：拒绝覆盖，界面报告冲突。后续可加冲突副本自动保存和版本恢复 UI。
- “另存为”路径视为一个新文档映射，首期默认创建新云文件。
- 可配置扩展名白名单，默认仅同步 `doc/docx/wps`, `xls/xlsx/et`, `ppt/pptx/dps` 等 Office 文档格式。

### 4.1 本地原文件与云端文件的关系

- 从本地路径打开并保存的文档继续留在原位置；加载项只上传文件内容，不搬动或覆盖本地原文件。
- 本机用随机 `machineId` 与规范化路径的 SHA-256 摘要识别本地来源。完整本地路径只在 WPS 客户端本地使用，不发送给服务端。
- 服务端用 `fileId` 作为云端文档身份，文件名仅用于展示，不作为唯一键。不同设备或不同本地路径可分别绑定同一个 `fileId`。
- 从云端列表打开文档时，加载项将内容缓存在 `%APPDATA%\\WPSPersonalCloud\\cache\\<fileId>\\v<version>\\<filename>`，再通过 WPS `Documents.Open` 打开并激活。该缓存是正式本地文件，不使用 WPS 下载器临时生成的 `.jsdownload` 文件作为工作文档。
- 缓存路径按云端 `fileId` 和不可变版本号区分。相同版本已缓存时直接打开；新版本写入新的版本目录，不覆盖旧版本或用户原来的本地文件。
- 云端缓存打开后保存时，缓存路径也会绑定到同一 `fileId`，并沿用上传票据的 `expectedVersion` 检查。上传成功后云端生成新版本；版本冲突时保留本地缓存文件并报告冲突。
- 当前版本没有“恢复/覆盖到原始本地路径”操作。若以后增加该功能，必须由用户显式选择，并在覆盖前检测待同步状态与目标文件变化；默认云端下载不覆盖本地原文件。

### 4.2 云端下载与缓存流程

1. 客户端请求下载票据；服务端返回短时下载地址及对应的 `fileId`、`name`、`version`、`size`。
2. 客户端构造该版本的稳定缓存路径。如果文件已存在，直接将缓存文件关联到云端文件并在 WPS 中打开。
3. 如果未缓存，调用 `OAAssist.DownloadFile`。WPS 回调可能同时包含临时路径和响应信息；客户端只提取路径字段，不把响应头文本拼进文件路径。
4. 客户端通过 WPS `FileSystem.copyFileSync` 将下载器的临时文件复制到版本化缓存路径，并确认目标文件存在；之后才登记本地路径映射并调用 `Documents.Open`/`Activate`。
5. 版本化目录不覆盖其它云端版本或本地原件。缓存清理和用户指定的“恢复到原路径”尚未实现。

## 5. 服务端 API

| 方法 | 路径 | 作用 | 鉴权 |
|---|---|---|---|
| GET | `/api/health` | 健康检查 | 无 |
| GET | `/api/files?parentId=root` | 列举云目录 | Bearer Token |
| POST | `/api/sync-ticket` | 创建/更新文档并签发上传票据 | Bearer Token |
| GET | `/api/files/:id` | 查询云端文件当前版本和 SHA-256 摘要 | Bearer Token |
| GET | `/api/files/:id/download-ticket` | 返回下载地址及当前版本元数据 | Bearer Token |
| POST | `/api/upload?ticket=...` | 接收 multipart 文件并写入新版本 | 短时 HMAC 票据 |
| GET | `/api/download?ticket=...` | 传输文件版本 | 短时 HMAC 票据 |

存储层用版本 blob 和 JSON 元数据构成，版本号单调递增。`WPS_CLOUD_DATA_DIR` 指向用户配置的存储根目录；生产部署需限制该目录权限，并可通过反向代理或后续存储适配器映射到 NAS/S3。

下载票据响应包含 `downloadPath`、`fileId`、`name`、`version` 和 `size`。文档查询 API 另返回当前版本 `sha256`，供客户端差异检查；旧元数据缺少摘要时，服务端根据当前 blob 懒计算并回写。客户端以 `fileId + version` 为稳定缓存身份；下载内容通过签名票据获取，长期 Bearer Token 不放进下载 URL。

## 6. 安全设计

- 业务 API 使用 Bearer Token；上传/下载使用短时 HMAC 票据，限制文件 ID、文件名、版本、有效期和操作类型。
- 服务默认只绑定回环地址。公网部署须使用 HTTPS 反向代理、防火墙和强随机密钥。
- 加载项仅在本地设置中保存服务地址、目录和访问令牌。原型阶段令牌保存在加载项存储中；正式个人版应使用 Windows Credential Manager/DPAPI 的本地辅助进程保管长期凭证。
- 服务端限制上传大小，拒绝路径穿越，并避免根据用户提交的文件名拼接磁盘路径。
- 保存失败不会删除、回滚或覆盖用户本地文件。

## 7. WPS 加载项部署

加载项包含 `ribbon.xml`、`index.html` 和 `main.js`。个人本机安装使用 WPSJS Windows 本地加载项目录 `%APPDATA%\kingsoft\wps\jsaddons\` 和 `publish.xml` 注册文件，不调用官方发布服务。`client/addin/scripts/Install-WpsPersonalCloud.ps1` 将 Writer、ET、WPP 构建资源复制到本机版本目录并合并三个 `jsplugin` 注册项；卸载脚本只移除本插件的注册和版本目录，修改注册文件前会生成备份。具体命令见 `client/addin/README.md`。不建议修改 `oem.ini` 或旧 `jsplugins.xml`。

该本机安装路径参考 WPSJS Windows 调试/离线加载项使用的目录结构。安装脚本和注册尚待用户本机生产构建验收；不同 WPS 发行版可能限制本地离线加载项。加载项安装并启用后，须随 WPS 启动并在对应文字、表格、演示组件中运行，才能注册保存事件。首版以 Windows 桌面 WPS 为目标，确认实际版本的 JSAPI 事件覆盖后再扩展其它平台。

## 8. 实施阶段

### 阶段一：当前原型

- Node.js 零依赖文件服务、目录列举、签名票据、分版本上传/下载。
- WPS 加载项设置面板、保存事件监听、保存后上传和状态提示。
- 覆盖从本地打开的已保存文档、云端目录列表、按 `fileId + version` 缓存并打开云端文档。

### 阶段二：客户端验证

- 已在用户本机完成新一轮云端下载打开验证：加载项将 WPS 下载器返回的临时文件复制到按 `fileId + version` 区分的缓存路径，并成功通过 WPS 打开流程。此项为用户反馈的客户端验证结果。
- 用户已反馈 Writer、ET、WPP 三类文档均完成测试；本轮未收到具体 WPS 版本号和逐项用例结果，因此不将未提供的测试细节记为已验证。
- 2026-10-19 已成功生成 Writer、ET、WPP 三种生产构建产物，输出分别位于 `client/addin/dist/`、`client/addin/targets/et/dist/`、`client/addin/targets/wpp/dist/`。已核对三个入口的 HTML、共享 `main.js`、面板资源和 `ribbon.xml` 均存在，且 ET/WPP 入口分别声明 `et`/`wpp` 类型。构建目录已加入 Git 忽略规则。
- 尚未执行 WPS 官方发布流程或在用户 WPS 中安装生产包；因此当前只完成构建检查，生产包注册、加载及升级/卸载仍待本机验收。构建器提示经典脚本 `main.js` 不参与 Vite 打包；它由构建插件作为独立资源复制，三个入口 HTML 均引用该文件。
- 在目标 WPS Windows 版本验证首次保存、普通保存、另存为、不同活动文档、关闭文档、自动保存和上传失败重试。
- 验证自动保存开关：连续编辑时空闲计时会重置；停止编辑默认 5 秒后落盘；云端内容相同则不创建新版本；仅本地内容变化时上传新版本；远端先变化时报告冲突；关闭时停止定时保存和后台检查。
- 验证大文件内容摘要计算在目标 WPS 版本上的内存占用与响应时间。
- 明确 Writer、ET、WPP 事件参数差异并修正适配（Writer、ET、WPP 已按组件分流；WPP 以选区变化作近似触发，仍需在目标客户端验证是否能覆盖实际编辑行为）。
- 已添加三种组件的生产构建结果与本机第三方安装/卸载脚本和 README 操作说明；实际本机安装、重启后加载和卸载仍待验收。

### 阶段三：稳健性和存储扩展

- Windows 安全凭据辅助进程、持久化上传队列、冲突副本、版本历史和恢复。
- 服务端 SQLite 元数据与对象存储适配，备份/清理策略。
- 可选同步目录与受监控本机进程，补充加载项被卸载或未加载时的保存监听空窗。

## 9. 已知限制

- 加载项必须安装、启用并加载；未运行时无法收到 WPS JSAPI 事件。辅助进程监控属于增强方案。
- WPS API 文档虽列有保存后事件，但不同组件/版本的回调签名和自动保存覆盖面需要真实客户端验证。
- 首版是单人/多设备的文件版本同步，不是并发协作编辑器。
- 云端打开文件缓存位于 Windows `%APPDATA%` 下，按版本保留；首版没有缓存清理功能，也不会将下载文件覆盖到原始本地路径。
- 服务端当前用本机 JSON 元数据文件，适用于个人原型；生产部署需数据库、备份和存储配额策略。
